# November 6, 2026 pricing audit

Version 0.2.11 rechecks the providers in the existing coding/text catalog and adds GPT-6.1 Terra, released on October 26. Claude, Codex and OpenCode still share the bundled pricing file. These are API-equivalent estimates, not subscription bills or quota conversions.

## Updated mapping

Prices are USD per million tokens.

| GPT-6.1 Terra / request input | Input | Output | Cache read | 30-minute cache write |
| --- | ---: | ---: | ---: | ---: |
| Standard, ≤272K | 1 | 5 | 0.05 | 1.25 |
| Standard, >272K | 2 | 7.50 | 0.10 | 2.50 |
| Fast/Priority, ≤272K | 2 | 10 | 0.10 | 2.50 |
| Fast/Priority, >272K | 4 | 15 | 0.20 | 5 |

Sources: [OpenAI pricing](https://developers.openai.com/api/docs/pricing), [GPT-6.1 Terra model details](https://developers.openai.com/api/docs/models/gpt-6.1-terra) and the [October 26 release entry](https://developers.openai.com/api/docs/changelog).

Both general and Codex mappings recognize the model and normal snapshot/context suffixes. The long-context rate applies to the entire request once all input partitions exceed 272,000 tokens; output does not count toward that threshold. Explicit Codex Fast/Priority records use 2× API rates. No Terra Ultrafast rate is published in the checked table, so none is inferred. Generic Claude/OpenCode records do not provide service-tier attribution and retain standard estimates.

The model also offers 12-hour writes at $2.50 before long-context adjustments. Local usage currently lacks a distinct OpenAI retention field, so the existing short-retention convention is retained, including the general catalog's legacy write-slot names. This release does not silently reinterpret a generic `cache_write_1h` value as a 12-hour OpenAI write.

## Historical protection and validation

- All pre-existing model entries, fallback choices, time schedules and `price_history` segments remain unchanged; a structural comparison against 0.2.10 verifies this.
- Previously unrecognized GPT-6.1 Terra records now use their own prices rather than older fallback estimates. Those records can therefore be corrected during the automatic pricing-keyed cache rebuild; original logs and old caches are preserved.
- Regression tests cover exact/variant IDs, both catalogs, all input/cache partitions, reasoning-token handling, the 272K boundary, speed multipliers and existing historical rates.
- Before editing, the existing interactive test `testRepeatedControlClicksDoNotEndTrackedSubmenu` reproduced its two failures on unchanged 0.2.10 in this desktop session. This release does not modify its UI code; the separate live-account test remains opt-in.
- After the update, all 35 pricing tests passed. Excluding the previously failing interactive test, the broader suite ran 119 tests with no failures and one opt-in live-account test skipped.
- Quota selection, the local-only 5/30-minute activity schedule, menu debounce, login state and preferences are unchanged.
