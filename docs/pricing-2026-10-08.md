# October 8, 2026 pricing audit

TokenMeter estimates API-equivalent token costs, not subscription charges or weekly Codex capacity. Claude, Codex and OpenCode share the bundled catalog. Quota reads and sign-in behavior are unchanged by this release.

## Updated mappings

Prices are USD per million tokens. These are standard on-demand API prices unless the row names a service tier.

| Model / prompt length | Input | Output | Cache read | Cache write 5m / 1h |
| --- | ---: | ---: | ---: | ---: |
| Sonnet 5.5, from October 7 | 2 | 10 | 0.10 | 2.50 / 4 |
| Sonnet 5.5, before October 7 | 2 | 10 | 0.20 | 2.50 / 4 |
| Haiku 5.5, ≤100,000 input tokens | 0.10 | 0.50 | 0.01 | 0.125 / 0.20 |
| Haiku 5.5, >100,000 input tokens | 0.50 | 2.50 | 0.05 | 0.625 / 1 |
| GPT-6 Astra Ultrafast, ≤272,000 input tokens | 60 | 300 | 6 | 75 / 75 |
| GPT-6 Astra Ultrafast, >272,000 input tokens | 120 | 450 | 12 | 150 / 150 |

Anthropic's [October 7 release notes](https://platform.claude.com/docs/en/release-notes/overview) explicitly announce Sonnet 5.5's cache-read reduction and Haiku 5.5's launch. The [API price table](https://platform.claude.com/docs/en/about-claude/pricing) supplies both Haiku input-length tiers and all cache rates. Sonnet 5 and Haiku 4.5 retain their existing prices; they are not aliases for the new models.

Haiku prompt length is fresh input plus cache reads and both cache-write partitions, excluding output. Exactly 100,000 input tokens uses the lower tier. Above that boundary, every token partition uses the higher tier, not just the excess input.

OpenAI's [September 29 changelog](https://developers.openai.com/api/docs/changelog) announces Astra Ultrafast; [Ultrafast documentation](https://developers.openai.com/api/docs/guides/ultrafast-mode) requires an explicit `service_tier: "ultrafast"`. Its [API prices](https://developers.openai.com/api/docs/pricing) are 6× standard for each partition, including long context. Only Codex records carrying that service tier use this multiplier. Ordinary Astra requests and Fast/Priority retain their existing rates; generic Claude/OpenCode records do not carry this service-tier distinction through the pricing interface.

This audit focuses on current coding/text-model mappings and existing billing rules. It is not a claim that every older model, specialized modality, processing tier or regional endpoint has been fully mapped. Older Qwen multi-band context prices remain previous catalog estimates; the cache-mode limitations in the [September audit](pricing-2026-09-29.md) also still apply. Batch/Flex, regional uplifts, time-based storage, tool charges and account-specific discounts remain excluded. Anthropic Fast mode is not inferred from generic usage records.

## Historical protection and cache rebuilding

- Sonnet 5.5's complete previous entry is retained strictly before **2026-10-07 00:00 UTC**. The official announcement specifies a date, not an exact instant; this follows the existing catalog's date-only convention, not a verified second-level billing switch.
- Astra's complete previous Codex entry is retained before **2026-09-29 00:00 UTC**. Explicit Ultrafast records from its launch onward now use their published rate rather than an unsupported-tier standard estimate.
- New Haiku 5.5 IDs and dated/context variants use their own prices, correcting former fallback estimates. No old Haiku or Sonnet model is repriced to the new generation.
- Existing historical revisions and fallback models are unchanged. The new catalog fingerprint rebuilds cost caches using each record's event timestamp. Source logs and previous caches are not deleted.
